# Qur’an Janab AI

An installable Flutter mobile app with a white Qur’an reader, English/Arabic
teaching preferences, Hifz mode, and an experimental GPT-Live 1 integration.

**Version 0.1.0 — source implementation, not a production release.**

## What is included

- Offline Arabic reader: all 114 surahs / 6,236 ayat, unchanged upstream text.
- Surah search, ayah-range selection, adjustable text size, English/Arabic UI.
- Hifz mode, manual hints, local practice history, and history deletion.
- Demo practice with manually advanced word highlighting, correction, and retry.
  Demo mode never opens the microphone or pretends to assess audio.
- Native WebRTC client and FastAPI backend for GPT-Live 1 sessions.
- API keys stay on the server. The app uses a separate personal backend token.
- Server-side transcript checks, possible-difference review requests, retry
  checkpoints, deduplication, time limits, and session-close handling.
- A full product plan, tests, corpus checksum, and an Android CI build workflow.

## What has been verified here

- Backend tests run locally: authentication, corpus integrity, range/language
  validation, missing-key behavior, mocked Live setup and closure, and sequence
  tracking including partial words, repetition, self-correction, and retry.
- Dart source is syntax-parsed. This is not Flutter analysis or compilation.
- See `docs/BUILD-STATUS.md` for final counts and limitations.

**No APK or iOS build has been produced in this workspace.** Flutter and Android
SDKs were absent, and Flutter SDK downloads timed out. Native platform scaffolds
are generated by `scripts/bootstrap_mobile.py` using your installed Flutter SDK.
The repository includes source and reproducible setup, not a claim of a tested
phone binary. GitHub CI has not run because repository access was unavailable.

**Live audio has not been tested against an OpenAI account or a physical phone.**
This implementation follows the documented Live protocol and still requires an
API key, account access to `gpt-live-1`, an HTTPS backend, and device validation.

## Quick start: Android demo

Install Flutter stable (Dart 3.9 or later), Java, and the Android SDK, following
https://docs.flutter.dev/install. Then from the repository root:

```bash
python3 scripts/bootstrap_mobile.py
cd apps/mobile
flutter pub get
flutter analyze --no-fatal-infos
flutter test
flutter run
```

Choose **Start practice → Explore demo**. No server, API key, or microphone
permission is required for demo reading. Demo highlighting advances with the
Next word button; it is never driven by fake audio recognition.

To build an installable debug APK:

```bash
flutter build apk --debug
```

Output: `apps/mobile/build/app/outputs/flutter-apk/app-debug.apk`.
This is a development build. Configure your own signing before distributing a
release. Never commit signing keys. iOS scaffolds are generated too, but iOS
requires a compatible macOS/Xcode environment, dependency setup, and signing.

## Start the backend

Python 3.12 is the tested interpreter. From the repository root:

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r services/api/requirements-dev.txt
cp .env.example .env
```

Set these values in `.env`:

- `OPENAI_API_KEY`: your API project key, used only by the server.
- `APP_ACCESS_TOKEN`: a new random token of at least 24 characters. Generate with
  `python3 -c "import secrets; print(secrets.token_urlsafe(32))"`.
- `MAX_SESSION_SECONDS`: 600 by default; server enforces a maximum of 900.

Load the environment with your shell or deployment secret manager. The `.env`
file is a template and is not automatically loaded by the application:

```bash
set -a
source .env
set +a
PYTHONPATH=services/api python -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

Use a single worker for this personal development backend. Its active-session
state and start limits are in process, not a shared database. Deploy behind
HTTPS and replace the shared development token with per-user authentication
before offering it to other users.

## Connect the mobile app

In **Settings**, enter the backend URL and the `APP_ACCESS_TOKEN`. **Never paste
the OpenAI API key into the phone app.** The token is kept only in memory and
must be entered again after restarting the app.

- Android emulator, debug build: `http://10.0.2.2:8000`.
- Android USB debugging: `adb reverse tcp:8000 tcp:8000`, then
  `http://127.0.0.1:8000` in the app.
- Physical phone over a network / release build: a valid HTTPS backend URL.

Choose a short passage of at most 10 ayat, choose **Live beta**, read and tick
the experimental-mode acknowledgment, then start. The reader remains available
for longer passages in demo mode. The live prompt receives the exact selected
reference, even in Hifz mode.

Start directly at the first displayed word. Spoken introductions or reciting
outside the selected range can require a retry. Select a new range for a new
starting point. Live pause closes the paid session; restart begins at the
selected passage's first word in this version.

## Accuracy boundaries

This is **transcript-based word-sequence matching**, not a pronunciation or
tajwīd assessor. The transcript can silently repair a student's pronunciation.
The app therefore asks to review a *possible* difference rather than claiming a
confirmed error. It does not publish accuracy scores or claim measured latency.

The matcher tolerates partial transcript fragments, immediate self-correction,
and repeating the previous word. A candidate needs following matching words.
Unanchored speech becomes “unclear.” It has not been teacher-calibrated.

All review speech stays in the selected English/Arabic explanation language;
Arabic recitation never changes the setting. Generated speech remains a model
output and requires evaluation. Reference recitation audio is intentionally
absent until recordings have cleared rights and reviewed phrase boundaries.

Remote tutor audio is gated while reciting and enabled for review requests.
The microphone remains active during a review, then retry re-gates output.
There is a local haptic cue, but **no pre-recorded spoken pause cue** yet.
Native echo cancellation, volume routing, Bluetooth, and overlap behavior must
be tested on devices. No target latency has been measured.

## Privacy and operating limits

No raw recording or transcript is written by this app/backend. The server keeps
short transcript state in memory for alignment. Local history contains passage,
duration, review count, and whether it was a demo. OpenAI receives audio during
live sessions; provider retention follows your API account configuration.
`store: false` is requested and does not itself promise zero provider retention.

The development backend allows one active session and 12 starts per hour per
process. Sessions have a duration limit. Disconnecting the app requests closure.
If provider finalization cannot be confirmed, the UI warns rather than claiming
that billing definitely stopped. Configure provider spend limits separately.
